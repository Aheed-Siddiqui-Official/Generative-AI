there are 3 types of text splitting

=>1) Character Based Splitting => it will make chunks on the basis of characters quantity e.g. 10 characters also includes spaces in the characters
=>2) Token Based Splitting => Divides documents into chunks based on the number of tokens not characters
Since LLMs process tokens instead of words this method aligns better with how models actually read text

depends on chunk size
e.g. [hello how are you] => ["hello" "how" "are" "you"] => ["hello how" "are you"] 

when chunks are created they also contain meta data and page_content

=> Recursive Text Splitting => divides the document into chunks based on the meaning and structure of the text, rather than characters or tokens. The goal is to keep complete ideas together so that each chunk contains a coherent piece of information

=> 3 core retrievals strategies => 
1) Similarity Search

the system compares the query vector with document vectors using similarity metrics like : 
Cosine Similarity => x, y axis line graphs
Dot Product
Euclidian Distance => big sphere with multiple clusters using KNN 
The retriever finds the most similar distance

2) MMR (Max Marginal Relevance)

imagine building RAG system, knowledge base consisting of lots of chunks, query => similarity search will do semantic meaning and all 3 chunks will be fetched that cause token usage, context window occupation, information diversity loss, LLM dont learn new things

MMR retrieve different but relevant and diverse documants

3) MultiQuery Retriever

imagine building RAG system, knowledge base consisting of lots of chunks, query => the result will be chunk 1, 3 because the query is limited => User query => LLM generated multiple queries => retriever searches for each query => combine all retrieved results
